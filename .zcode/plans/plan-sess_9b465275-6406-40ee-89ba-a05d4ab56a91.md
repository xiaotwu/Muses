## 勘探关键结论
- **无 VersionedSchema/MigrationPlan** — schema 是单一未版本化 `Schema`。Artist @Model 用**加法方案**:新建 Artist entity + 加到 v1 schema(SwiftData 轻量迁移自动建表)+ 加 optional 关系(`Track.artistRef: Artist?`、`Album.artist: Artist?`)+ 首次启动 back-fill。保留 `Track.artist: String` / `Album.albumArtist: String` 不删,避免破坏性迁移。
- **EnrichmentEndpoint** 有 4 个 builder,无 artist endpoint。iTunes Search 返回 `artistId`/`artistLinkUrl`/`primaryGenreName` 但当前未用。扩展 `itunesArtistSearch(term:)` (entity=musicArtist) 即可。
- **ArtworkCache** 按 content hash 存储,无"artist"概念,可直接存 artist 图片(hash 存 `Artist.artworkHash`)。
- **全局搜索**:RootView overlay 系统(`showQueue`/`showNowPlaying` 模式)可直接加 `showSearch`。`QueueSource.search` 已存在。QueueDrawerView 是 overlay-panel 最佳模板。YouTubeSearchView 是搜索结果 UI 模板。
- **无 debounce**:SongsListView/ArtistsView 每次按键全量 fetch+filter+sort。SongRow 每行有 `@Query playlists`(每行重复查询)。
- **List 已虚拟化行渲染**,但 backing array 全量物化。个人库 <5000 曲无性能危机,但 debounce + 减少 per-row 查询是明显改进。

## 风险与缓解
- **Artist @Model 加法迁移**:加 optional 关系到 Track/Album,SwiftData 轻量迁移加 nullable 列 — 安全。back-fill 用 UserDefaults flag 一次性运行。
- **全局搜索 overlay 性能**:debounce 250ms + 本地结果即时/YouTube 异步。本地 fetch 全量 filter 对 <5000 曲 <10ms,可接受。
- **SongRow @Query per-row 移除**:需确保 context menu 仍能访问 playlists。通过参数传入,父 view 持有 @Query。
- **screencapture 时机**:app 启动后需等待 UI 渲染完。`sleep 3` + screencapture。
- **AppleScript 导航**:可能无法精确点击 sidebar(无 accessibility identifier)。用 `screencapture` 全屏截图 + Read 工具视觉检查替代精确交互。
