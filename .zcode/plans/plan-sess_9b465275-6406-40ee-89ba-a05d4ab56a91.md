## Task 3: Play-history recording (foundation for item 4)

**Gap discovered:** `Track.lastPlayedAt` / `Track.playCount` are declared but NEVER written anywhere — `mostRecentlyPlayedAlbum()` always returns nil, `RecommendationService` has no real input. Must fix before "Recently Played" can work.

- **`Services/Playback/PlaybackService.swift`**: add `modelContainer: ModelContainer` to init (store it). At the point a track becomes current (`playTrack` / `next` / `previous` / `load`), record history on a background `Task`:
  ```swift
  private func recordPlay(_ id: UUID) {
    let container = modelContainer
    Task.detached(priority: .utility) {
        let ctx = ModelContext(container)
        if let t = try? ctx.fetch(FetchDescriptor<Track>(predicate: #Predicate { $0.id == id })).first {
            t.lastPlayedAt = Date(); t.playCount += 1
            try? ctx.save()
        }
    }
  }
  ```
  Call it whenever `currentItem` is set (both local & YouTube tracks are `Track` models → covers "本地和在线播放").
- Verify this unblocks `RecommendationService` (becauseYouListened now populated) as a bonus — no NewView change needed.

## Execution order & risks
Task 1 (Sparkle→GitHub, isolated infra) → Task 2 (font, trivial) → Task 3 (play history, foundation) → Task 4 (Home, depends on 3) → Task 5 (PlayerBar, independent UI). Then: `swift build`, `swift test --no-parallel` (sandbox off for audio), `make app`, commit, push, memory (`muses-phase14-done.md` + MEMORY.md pointer).

**Risks:**
- Sparkle removal touches the release pipeline (build-app.sh, sign-update.sh, Makefile, Info.plist, 3 test files). Mitigation: keep notarize+dmg intact; only strip Sparkle-specific steps; update/delete the 2 Sparkle tests surgically. Verify `make app` still builds a working .app (no Sparkle.framework needed).
- Play-history recording via `Task.detached` + new `ModelContext` could race SwiftData. Mitigation: detached context with its own ModelContext is the documented safe pattern; save with `try?`.
- MonteCarlo registration timing: must register before any view uses `.custom("MonteCarlo")`. Mitigation: call `FontLoader.registerMonteCarlo()` at the very top of `MusesApp.init` (synchronous, before services). If registration fails, `.custom` silently falls back to system — no crash.
- GitHub API in tests: don't hit the network in tests; test `UpdateService` with a mock URLProtocol or by injecting a fetched-JSON. Keep the existing 175 green by not breaking unrelated suites.
