# Muses 阶段 3 — 在线与同步 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement task-by-task. Steps use `- [ ]` checkbox syntax.

**Goal:** 在阶段 2 TIDAL 体验层之上,补齐在线能力:yt-dlp 桥接 + YouTubeStreamEngine(注入 AVAudioEngine,降级 AVPlayer)+ YouTube 歌单导入/管理/本地附加 + 混合队列引擎调度 + 歌词服务(LRCLIB + 本地 .lrc)+ Sparkle 自动更新集成 + yt-dlp 二进制打包。阶段结束产出可演示的本地+YouTube 混合播放体验。

**Architecture:** 沿用阶段 1/2 分层。新增 `Infrastructure/YTDlpBridge.swift` + `StreamURLCache`、`Services/Playback/YouTubeStreamEngine.swift`、`Services/YouTube/YouTubeImportService.swift`、`Services/Lyrics/LyricsService.swift`、`Domain/YouTubeImport.swift` + `YouTubeImportItem.swift`、`Features/YouTube/`、`Features/NowPlaying/LyricsView.swift`、`Features/Settings/YouTubeSettingsView.swift`。`PlaybackService` 改为双引擎调度(按 `QueueItem.source` 选 `LocalAudioEngine` / `YouTubeStreamEngine`)。`Package.swift` 引入第一个外部依赖 Sparkle 2。

**Tech Stack:** Swift 6.0 / Xcode,SwiftUI,SwiftData,AVFoundation,MediaPlayer,Process(yt-dlp 桥接),URLSession(LRCLIB),Sparkle 2(SPM),macOS 14 SDK 最低部署。

## Global Constraints

- 最低部署 **macOS 14**,仅 **arm64**。
- **合规边界**(沿用 spec §2.1):yt-dlp 仅个人使用,不分发音频,不上 App Store;YouTube 内容受 YouTube ToS 约束,下载行为遵守当地法律;本地附加永不调 YT 写 API;Sparkle 用 EdDSA 签名 appcast + Developer ID 公证。
- **第一个外部依赖**:Phase 3 引入 Sparkle 2(SPM)。yt-dlp 不是 Swift 依赖,是随应用打包的二进制,通过 `Process` 调用。
- 联网测试用 stub `URLProtocol` 或 mock binary,不打真实网络/不调真实 yt-dlp。
- 不破坏阶段 1/2 的 47 个测试;每个任务后跑全量 `swift test --no-parallel`。
- 品牌色沿用 `BrandColors`;新视图按深色实现,浅色留 Phase 4。
- 每任务结束 commit,前缀 `feat:`/`test:`/`chore:`/`refactor:`/`fix:`。

## Task 2: YTDlpBridge

**Files:** `Infrastructure/YTDlpBridge.swift`, `Tests/.../YTDlpBridgeTests.swift`

`@MainActor final class YTDlpBridge` — 通过 `Process` 调用 yt-dlp 二进制。
- `init(binaryPath: String? = nil)` — 默认 `Bundle.main.url(forResource: "yt-dlp", withExtension: nil)?.path`,fallback `which yt-dlp`
- `func resolveStreamURL(videoId: String, quality: String) async throws -> URL` — 执行 `yt-dlp -f <quality> --no-playlist -g "https://youtu.be/<id>"`,解析 stdout 首行 URL
- `func fetchPlaylist(url: String) async throws -> [YTDlpPlaylistEntry]` — `yt-dlp --flat-playlist --dump-json <url>`,逐行 JSON 解析(title, id, duration, uploader)
- `func version() async -> String?` — `yt-dlp --version`
- `struct YTDlpPlaylistEntry: Codable, Sendable { id, title, uploader, duration }`
- Errors: `YTDlpError.notFound / exitCode(Int, String) / timeout / parseFailed(String)`

**设计要点:** Process 执行用 `Task.detached` + pipe,避免阻塞 main actor。超时 30s。`quality` 映射:`bestaudio` → `-f "bestaudio[ext*=m4a]/bestaudio/best"`,`128k` → `-f "ba[abr<=128]"`。

**测试 (4):** 用 fixture shell 脚本(输出预设 stdout)作为假二进制,验证 URL 解析、playlist JSON 解析、非零退出码报错、超时。二进制路径可注入。

**Downstream contract:** YouTubeStreamEngine (Task 3) 用 `resolveStreamURL`;YouTubeImportService (Task 5) 用 `fetchPlaylist` + `version`。

- [ ] 实现 YTDlpBridge
- [ ] 4 个测试
- [ ] commit

## Task 3: YouTubeStreamEngine

**Files:** `Services/Playback/YouTubeStreamEngine.swift`, `Tests/.../YouTubeStreamEngineTests.swift`

`@MainActor final class YouTubeStreamEngine: PlayerEngine` — 复用 `LocalAudioEngine` 的 AVAudioEngine 图(player → eq → mixer)。
- `load(_ track:)`: 
  1. `guard let videoId = track.youTubeId` else throw `.sourceUnavailable`
  2. `StreamURLCache.default.get(videoId)` 命中 → 直接用;未命中 → `bridge.resolveStreamURL(videoId:quality:)` → 缓存
  3. **主路径(AVAudioEngine)**:异步下载到临时文件 `~/Library/Caches/Muses/streams/<videoId>.<ext>`,设 `state.buffering = true`,下载完 `AVAudioFile(forReading:)` → `player.scheduleFile`,`state.buffering = false`,`state.source = .youtube`
  4. **降级(AVPlayer)**:AVAudioFile 打开失败/流不稳 → `AVPlayer(url: audioURL)`,EQ/频谱不可用,`state.quality.codec = "native"`
- `play()/pause()/toggle()` — AVAudioEngine 路径同 LocalAudioEngine;AVPlayer 路径委托 AVPlayer
- `seek(to:)` — AVAudioEngine 用 scheduleSegment;AVPlayer 用 `.seek(to:)`
- `setEQ(_:)` — AVAudioEngine 路径同 LocalAudioEngine;AVPlayer 路径 no-op
- `installSpectrumTap/removeSpectrumTap` — AVAudioEngine 路径同 LocalAudioEngine(SpectrumTap on eq);AVPlayer 路径 no-op(handler 收到全零帧)
- position tracking:AVAudioEngine 用 Timer + sampleTime;AVPlayer 用 `AVPlayer.addPeriodicTimeObserver`
- 403/过期:load 失败 → `StreamURLCache.invalidate` → 重试一次 → 仍失败 throw `.sourceUnavailable`

**测试 (4):** 注入 mock YTDlpBridge(返回 fixture 音频文件 URL)+ in-memory StreamURLCache。验证:load 成功设 state.source=.youtube;load 失败设 state.error=.sourceUnavailable;buffering 翻转;AVPlayer 降级路径(mock bridge 返回无效 AVAudioFile URL 触发降级)。

**Downstream contract:** PlaybackService (Task 6) 持有 YouTubeStreamEngine 实例,按 source 调度。构造函数 `init(bridge: YTDlpBridge, cache: StreamURLCache = .default)`。

- [ ] 实现 YouTubeStreamEngine
- [ ] 4 个测试
- [ ] commit

## 风险与缓解

- **Sparkle + 纯 SPM**:SPM executable 无自定义 Info.plist 字段,Sparkle 完整功能需 .app bundle。本阶段交付代码集成 + appcast 模板,实际自动更新验证留 release 打包(Phase 4)。若 Sparkle SPM 集成导致 `swift build` 失败,降级为仅引入依赖不初始化 controller(延后到 Xcode 项目)。
- **yt-dlp 二进制获取**:开发环境用 PATH fallback;打包时用 `copy-ytdlp.sh`。CI/分发需 chmod +x + codesign 签名并入(Phase 4 release)。
- **YouTube 流 URL 时效**:6h 缓存 + 403 自动重解析 + 重试一次。
- **跨引擎切换杂音**:load 前 `setVolume(0)` → load → `setVolume(volume)` 简单淡入;~50ms gap 基本无感。crossfade 选项留 Phase 4。
