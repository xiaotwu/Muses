## 2. 决策门 A：Home 产品承诺

当前批准规格选择“登录态 YouTube Music Web Session 适配器”，当前实现则是“官方 Data API 账号信号 + 公共发现”。这两者不是同一个产品承诺。

### 方案 A：隔离的登录态 Web Session 适配器

**能承诺的体验**

- 最接近真实 YouTube Music Home 的区段、顺序、Mix、继续收听和个性化内容。
- 可以满足“复刻登录态首页信息架构与内容”的现行批准规格。

**优点**

- 内容相关性和视觉参照最接近用户在 YouTube Music 里看到的首页。
- 能获得官方 Data API 没有公开的数据形态，例如个性化 Home 区段和 continuation。
- Home 与 Discover 可以保持清晰分工：Home 是账号个性化，Discover 是公共发现。

**缺点与成本**

- 私有 Web 数据形态会变化，维护成本高，必须有远端形状变化检测和快速降级。
- 需要隔离登录会话、Cookie、账号切换与过期处理，安全和隐私边界更复杂。
- 不能把 Web 会话当作持久用户真相、播放引擎或 Push 授权来源。
- 更难做确定性测试，发布必须带真实账号集成测试与失效演练。
- 即使技术上可实现，也需要单独评估服务条款与分发风险。

**发布条件**

- 独立进程或严格隔离的会话容器。
- 解析层只输出不可变值快照，SwiftUI 不接触 Web payload。
- 形状版本、账号 ID、获取时间、过期时间和 stale 原因都进入快照。
- 任意失败都回退到相同账号的最后成功快照，再回退到官方账号信号和公共发现。

### 方案 B：官方 API 范围内的近似首页

**能承诺的体验**

- 使用官方 YouTube Data API 的账号身份、点赞、订阅和自有歌单，结合公共发现与本地收听信号构建原生 Home。
- 不能承诺与真实 YouTube Music Home 的区段、顺序、Mix 或继续收听一致。

**优点**

- 接口稳定、权限可解释、测试可重复，适合长期维护和分发。
- 账号隔离、缓存、错误处理和数据保留边界更清楚。
- 不需要持有浏览器会话或解析私有 Web 数据。
- 可以更快达到“稳定可用”的发布门槛。

**缺点与成本**

- 无法真正复刻登录态 YouTube Music Home。
- 推荐质量受公共搜索和本地信号限制，容易出现内容稀疏或风格偏差。
- 必须正式修改产品文案与批准规格，避免把近似首页描述成完整复刻。

**发布条件**

- 产品目标改为“官方 API 范围内的个性化 Home”。
- 所有公共发现结果通过音乐可信度层，不能混入 SEO 合集或不可靠第三方内容。
- UI 清楚区分账号内容、公共发现、缓存内容和降级状态。

### 已批准方向（A+B）

用户于 2026-08-24 批准采用双层能力，但不混淆产品承诺：

1. **官方 API Home 是永远可用的稳定基线。**
2. **Web Session 是可关闭、可失效、可回退的增强能力。**
3. 没有 Web Session 时，产品只承诺官方 API 范围内的原生个性化 Home；只有增强能力实际可用时，界面才可以呈现并描述真实 YouTube Music 个性化区段。

这不是把两种方案混成一个不可测试的 Provider。代码层应有显式 `HomeCapability`、来源标识、独立账号缓存命名空间和可观察的降级链。官方基线与 Web 增强可以在同一页面编排，但每个 section 必须保留来源与新鲜度，不能静默混淆两种承诺。

## 3. 决策门 B：退役功能的“完全清除”边界

**状态：用户已批准完全删除，不保留迁移胶囊。**

用户决定完全清除扫描、本地导入、M3U、`LocalAudioEngine` 及关联功能；如果旧物理库不再承担运行、迁移或回滚职责，就直接移除以精简代码。

当前只读核对表明，标准启动已通过 `activeV3StorePath` 使用独立 V3 文件；活动库持续写入到 2026-08-24，而旧 `muses.sqlite` 最后写入停在 2026-08-20。旧库不是当前运行数据源，但生产 loader 仍在激活标记缺失时把它当作一次性导入源，且 P0-6 的 manifest 与同步真相校验尚未完成。因此批准最终删除，但实际删除属于 P0-6 验收后的收尾动作。

“完整清除”定义为：

- 主应用生产 target、测试 target、设置、菜单、命令、服务注入和运行时模型中不再存在退役功能。
- V3 物理库不再包含 `ScanRoot`、本地文件路径、M3U 状态或本地附加关系。
- P0-6 先完成全量 throwing export、manifest、逐类摘要和候选库复核；激活后在“旧库缺席”的条件下完成冷启动与用户真相验收。
- 验收通过后删除旧 `muses.sqlite` family、迁移 source copies、旧逻辑 snapshot、旧 Schema reader、兼容性分支和只服务于旧迁移的测试。
- 不创建独立迁移 target，不保留迁移胶囊，也不再支持从 pre-V3 安装自动升级；全新安装只创建当前干净 store。
- 删除当前活动库之外的旧 V3 候选与备份前，必须逐个解析活动指针并验证目标，禁止使用宽泛目录清理。

### P0-2 账号内容写入 guest 缓存

**状态：已完成，防回归。**

当前缓存 key 已包含 `accountChannelID`，同步输入构建也会传入账号；但异步强制刷新输入仍漏传账号，问题没有闭环。

**方案**

- 用不可为空的强类型 `HomeFeedScope` 代替裸可选字符串：`guest` 或 `account(channelID)`。
- `HomeDiscoveryInput` 必须显式持有 scope，所有构造器都要求传入，禁止默认 `nil`。
- 缓存目录按 scope 分区，而不只是在字符串 key 中拼接账号。
- 退出登录只清除会话和内存可见内容；账号缓存休眠，不显示给 guest。重新登录同一 channel 才可恢复。
- 切换账号时取消旧账号刷新任务；写缓存前再次核对任务捕获的 scope 与当前 scope。

**验收门槛**

- 覆盖同步 load、异步 reload、退出、A→B 切换、旧任务晚到五条测试。
- 任意缓存文件都能从路径和 manifest 判断所属账号。

### P0-3 Pull/Push 的三方同步语义

**状态：已完成；真实 Push 继续受 P0-4、P0-5 门禁。**

已将本地 item UUID、远端 `playlistItemID` 与内容 `videoID` 明确分层；远端身份首次出现时会在独立 SwiftData context 中持久化认领，重复视频按已有身份、位置和已识别邻居匹配。标题、艺人和时长改为可未知的描述元数据，不再参与结构指纹或制造伪冲突。

Pull 预览现在携带 Base、Local、Remote Shadow 三个 revision ID，并在接受前核对三者与当前 Local。接受后严格执行 `Local = resolvedMerge`、`Base = Remote Shadow`，本地尚未 Push 的修改不会被吞掉。Push 成功后重新读取并核对远端，只有验证后的 Remote 才能推进 Base；真实写入仍保持关闭，等待完整分页与安全续传完成。

**方案**

- 明确三种身份：本地 item UUID、远端 `playlistItemID`、内容 `videoID`。只有前两者可以标识重复条目。
- 未知时长、缺失标题等元数据使用 `unknown`，不与 `0` 或空字符串等价，也不参与结构变化判断。
- Pull 接受后：`Local = resolvedMerge`，`Base = Remote Shadow`。只有 Local 与 Remote 相同的部分才是共同基线。
- Push 完成并复核远端后：`Base = verifiedRemoteAfterPush`，不能直接用当前 Local 假定远端成功。
- 首次获得远端 `playlistItemID` 后立刻在独立事务中认领并持久化，重复视频按位置和邻居身份匹配。

**验收门槛**

- [x] 覆盖重复视频、本地新增 + 远端移动、未知时长、首次认领、Pull 后仍有待 Push 修改。
- [x] 任意时刻都能解释 Base、Local、Remote Shadow 的来源和 revision ID。
- [x] `swift test --no-parallel --filter YouTubePlaylistSync`：14 个测试通过；YouTube 相邻回归：58 个测试通过；全量：547 个测试、80 个套件通过。

### P0-4 大歌单静默截断

**状态：已完成；真实 Push 继续受 P0-5 门禁。**

分页读取现在返回 `PaginatedResult(items, completeness, pageCount, nextPageToken)`，正常路径持续读取到 `nextPageToken == nil`。默认安全上限提升为明确的 200 页（每页 50 条）；达到上限只会产生带 continuation 的不完整结果，不再返回伪装成完整的数组。

同步服务按页更新内部 `remotePartial` revision。取消、超时、配额、限流、解析或请求失败都会保存已读取条数、页数和下一页 token，并向界面报告“已读取 N 条”；后续检查从 token 继续。只有最后一页完成后，才在同一事务中发布 `remoteShadowRevisionID` 并清除临时 revision。

Remote Shadow 必须带有明确的完整性证明。旧 revision 没有分页元数据时视为不可信；不完整快照不能应用 Pull、不能恢复为 Local，也不能生成任何删除、移动或插入 Push 计划。

**方案**

- 对同步读取使用 `PaginatedResult(items, completeness, pageCount, nextPageToken)`。
- 正常路径一直读取到 `nextPageToken == nil`；设置高但明确的安全上限，只能产生 `.incomplete(reason)`，不能伪装成完整。
- 取消、超时、配额不足、解析失败都保留 continuation，并显示“只读取到 N 条”。
- 任何 Pull 删除或 Push 规划必须要求完整 Remote Shadow；不完整快照只能浏览和继续拉取。
- 分页按页持久化临时 shadow，完成后原子发布为可比较 revision。

**验收门槛**

- [x] 覆盖 0、1、149、150、151、200、5000 条，以及安全上限、配额、解析失败、超时和中途取消。
- [x] 验证分页按页持久化、失败后从 continuation 续拉、完成后原子发布 Remote Shadow。
- [x] 不完整远端快照永远不能触发 Pull 删除或 Push 的删除、移动、插入计划。
- [x] 聚焦：23 个测试通过；YouTube 相邻回归：66 个测试通过；全量：556 个测试、81 个套件通过。

### P0-5 Push 安全续传

**状态：部分实现，待真实测试歌单恢复演练。**

当前已有持久 journal 和逐操作保存，但冲突不阻止 journal 建立，预览后的远端变化不复核，远端成功后本地保存前崩溃仍可能重放 Insert。

**方案**

- `preparePush` 先要求三方冲突全部解决，再保存 `expectedRemoteRevisionHash` 和完整操作计划。
- `resumePush` 在首个写操作前重新拉取远端头部/完整 revision；hash 不同则作废预览并要求重新审查。
- journal 状态改为 `planned → started → remoteObserved → locallyCommitted`，每次转换都持久化。
- Insert 响应必须包含非空 `playlistItemID`；解析失败是失败，不得标记完成。
- 对崩溃窗口采用远端对账：根据视频、目标位置、邻居 `playlistItemID` 和批次前后 revision 判断 Insert 是否已发生，确认后认领，无法唯一判断则停在“需要人工确认”，绝不盲目重放。
- Push 全部操作结束后再次完整拉取远端，只有远端与目标一致才推进 Base。

**验收门槛**

- 覆盖每个状态转换点的故障注入、网络超时、429/5xx、空响应 ID、预览后远端改变和重复视频。
- 真实写操作开关默认关闭，直到沙箱/测试歌单通过完整恢复演练。

### P0-6 V3 原子迁移

**状态：已完成；旧库与迁移兼容链已清除。**

当前 Snapshot export 仍大量使用 `try? ?? []`，并且没有完整携带账号归属、远端身份、Base/Remote Shadow revisions 与未完成 journal。

**方案**

- 所有用户真相表使用 throwing fetch；任一表读取失败立即终止迁移。
- Snapshot 增加 manifest：格式版本、源 store ID、每类记录数、每类稳定摘要、导出完成标记。
- 纳入账号归属、`playlistItemID`、deletedAt、远端可写状态、Base/Remote Shadow revision、固定 revision、冲突决策和未完成 journal。
- 导入候选库后重新导出候选 manifest，与源 snapshot 做逐类计数、ID 集合、顺序和摘要核对。
- 激活只发生在完整导入和验证后，使用单一持久指针切换；失败时继续使用旧活动库。
- 指针切换本身不删除任何源库；成功冷启动并通过 manifest 验收后，执行已批准的 pre-V3 物理库与迁移代码清除。

**验收门槛**

- 对每一张表做读取失败注入；任何失败都不得生成可激活候选库。
- 覆盖重复 ID、缺失关系、磁盘不足、进程中止、journal 未完成、候选验证失败和回滚。
- 覆盖旧库缺席冷启动，并证明删除后不会重新创建、搜索或打开 pre-V3 路径。

## 5. P1 功能完整度卡

### P1-2 OAuth 读写权限分层

**状态：已完成，待真实授权拒绝/撤销验收。**

Context7 对当前官方文档的核对结果：只读账号访问使用 `youtube.readonly`；`playlistItems.insert/delete` 需要 `youtube`、`youtube.force-ssl` 或 partner scope；Google OAuth 支持通过 `include_granted_scopes=true` 做增量授权。

**方案**

- 首次连接只请求 `https://www.googleapis.com/auth/youtube.readonly`。
- 用户第一次启用 Push 时，再在上下文中请求 `https://www.googleapis.com/auth/youtube`；不为普通只读用户提前申请写权限。
- OAuth 请求加入 `include_granted_scopes=true`，能力判断读取 token 返回的实际 scope，而不是读取配置中的期望 scope。
- UI 显示“可读取账号内容”和“可管理歌单”两项独立能力；拒绝写权限不影响 Home、Pull 和播放。
- 降权需要撤销后重新连接，不能假定增量授权会自动移除既有广泛权限。

**验收门槛**

- readonly token 禁止构造 writer；Push 前置检查给出明确升级入口。
- 拒绝升级、取消授权、旧 broad-scope token、账号切换都有测试。

### P1-3 完整本地找回

**状态：已完成，待运行时交互验收。**

**方案**

- 歌单详情增加“版本与恢复”面板：revision 时间、来源、曲目数、修改摘要、固定状态。
- 选择 revision 后先显示有序 diff：新增、删除、移动、元数据变化和不可用项。
- 提供“恢复为当前本地版本”和“恢复为副本”两种操作；两者都绝不自动 Push。
- 固定/取消固定是明确动作；Recently Deleted 保留 30 天，固定版本保留到用户取消固定。
- 恢复前先自动保存 `beforeRestore` revision。

**验收门槛**

- 用户可以从 UI 浏览、比较、固定、恢复为副本和撤销最近一次本地恢复。

### P1-4 日历语义与收听热力图

**状态：已完成；主图为日期 × 小时热力图。**

**方案**

- “今天/本周/本月”使用 Calendar 的自然区间，不再使用滚动 24 小时、7 天、1 个月。
- 跨小时、跨天的收听事件按实际相交时长拆分到每个 bucket。
- 用 `ListeningHeatmap` 取代当前圆环作为主图：横轴为 0–23 时，纵轴为日期。
  - 今天：1×24。
  - 本周：7×24。
  - 本月：当月天数×24，可在固定高度内纵向滚动。
  - 全部：按星期×小时聚合为 7×24 的平均强度。
- 色阶表示时长，选中单元格显示准确时长、曲目和艺人；不只依赖颜色，零值、低值、高值有边界/纹理或数值提示。

**验收门槛**

- 覆盖时区、夏令时、跨午夜、周起始日、空数据和单个极端峰值。
- 颜色归一化规则固定且有图例，切换范围不会改变原始统计值。

### P1-5 图表无障碍与本地化

**状态：已完成，待运行时 VoiceOver 验收。**

**方案**

- 使用 Locale 感知的 `Date.FormatStyle`，不硬编码 `am/pm`；遵守系统 12/24 小时习惯。
- 热力图支持键盘二维导航、可见焦点、VoiceOver 行列标题和当前单元格值。
- 提供“数据表”切换，按日期列出非零时段，避免 VoiceOver 用户遍历数百个空单元格。
- 图表整体仍提供摘要：总时长、峰值区间、最活跃日期；摘要不能取代逐格数据。
- 高对比、Reduce Transparency 和色觉差异下都保留可辨认等级。

**验收门槛**

- VoiceOver 可以从摘要进入数据表并定位任意非零时段；键盘无需指针即可完成相同操作。

### P1-6 完全清除退役功能

**状态：已完成；退役功能、旧物理库与迁移链均已清除。**

**方案**

- 删除主应用中的 `LocalAudioEngine`、`ScanRoot`、扫描/文件导入服务、M3U、local additions 关系与所有入口。
- 删除继续保护这些行为的单元测试；仍需要音频引擎测试的地方改用 `FakePlayerEngine` 或 YouTube engine 测试夹具。
- `LibraryService` 只保留 YouTube-native 资料库职责，并拆除文件系统监听、元数据读取和 scan-root 生命周期。
- Package、构建脚本、设置、菜单、翻译、文档和测试 fixture 做反向引用扫描，确保不再编译或展示退役能力。
- P0-6 验收后删除旧物理 store family、迁移 source/snapshot、`MusesV3Snapshot` 一次性导入链路、旧 Schema reader 和活动指针缺失时的 legacy fallback。
- 当前 store loader 只打开显式活动的干净 store；全新安装直接创建当前 store，不探测 pre-V3 文件。

**验收门槛**

- 对生产与测试 target 运行关键字守卫：`LocalAudioEngine`, `ScanRoot`, `M3U`, `localAdditions`, `Add Local` 为零命中；没有迁移胶囊白名单。
- 新 V3 store、运行时依赖图和 UI 都不含本地文件能力。
- 应用支持目录只保留活动干净 store 及当前版本明确需要的 sidecar；旧库、迁移副本、快照和失效候选为零。
