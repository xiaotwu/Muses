# 剩余任务执行计划

日期：2026-09-19。批次 23 后当前基线为 609 tests／86 suites、Release 构建通过；R001 已完成 item 级及整歌单资源级真实写入闭环，批次 22／R002 已完成，批次 23 的实现阶段已收口。本计划取代旧计划中关于 R001、R002、R022 及已完成子项的待办描述，但不删除历史证据。

## 执行原则

- 当前实现顺序为 **R009／R016 → R014 → R015**；R023 证据可以随批次积累，但只有冻结同一 Release 后的完整矩阵才能关闭父项，正式发布最后进行。
- SwiftData schema、播放服务、Web Home helper、账号写入、缓存和打包均为高风险边界；每批只改变完成目标所需的最小范围，不夹带视觉重写或无关重构。
- 稳定身份只能来自 YouTube Music browse／playlist 或 YouTube channel／video 等明确来源。显示名、标题相似度和搜索排名只能作为候选，不得直接成为持久身份或合并依据。
- 真实账号写入必须绑定当前 OAuth 频道和精确资源 ID，执行前显式确认，执行后服务端复读；响应不确定时停止并保守恢复，不盲目重放。
- 每批最低验证为针对性自动化、`swift test --no-parallel`、Release 构建和 `git diff --check`。涉及 UI、网络、硬件或辅助功能的门槛必须补真实环境证据。

## 批次 22：R002 身份与多发行关系（已完成）

完成记录：[R002 多发行收口记录](r002-multi-release-closeout.md)。实现、自动化、Release 构建与真实资料库副本冷重开均已通过；源库没有权威专辑直接证据，因此保持 506 首曲目未解析，不按普通歌单或显示名制造发行关系。

目标：让一个 Track 能保留多个有来源证据的发行关系，同时继续以稳定 ID 隔离同名艺人／发行，不破坏现有 UUID、收藏、歌单、历史、笔记、书签和播放队列。

实施：

1. 先形成当前 `Track.releaseCatalogID`／`artistCatalogID`、`CatalogRelease`、`CatalogArtist` 和导入来源的只读数据盘点，列出直接证据、歧义候选及无证据行。
2. 设计显式 Track–Release 多对多关系及来源证据字段；现有单值字段只作为兼容输入，不继续承担多发行真值。艺人关系若同样需要多值，必须使用稳定 channel／browse ID，不按名称复制关系。
3. 将导入、在线专辑、目录刷新和历史身份应用统一到同一关系写入服务；目录投影保持可重建，用户真值与迁移收据保持持久。
4. 扩展现有预览、独立快照、逐表对账、显式应用和回滚，使多发行关系可以先审阅、失败可恢复、应用后可撤销。启动过程不得自动迁移用户资料库。
5. 在独立真实资料库副本上完成全量预览、应用、冷重开、对账和回滚；源库保持只读。

完成门槛：

- 同一视频的不同 Track UUID 不互相继承证据；同名不同艺人／发行不合并。
- 同一 Track 的多个权威发行可同时存在，顺序和来源确定；歧义候选保持未解析。
- 应用与回滚前后所有用户数据逐表对账，既有稳定身份不被较弱证据覆盖。
- schema 新建、旧库副本升级、失败注入、冷重开和完整回归通过。

## 批次 23：R009／R016 完整目录与 Home（实现阶段完成，条件验收待续）

2026-09-19 记录：稳定 browse 身份、艺人／发行结构化详情、六类搜索、播客、榜单、语言／地区游标、目录与 Home 物理缓存分区、七日 stale／expired 删除及匿名 Home shelf continuation 已实现并通过真实只读网络矩阵。完整回归为 609 tests／86 suites，Release 构建通过。真实账号 helper、订阅上传流、全局 Home continuation（须服务端实际提供）、播放上下文、VoiceOver／键盘／三语言与大结果集性能仍保留为条件验收；详见 [R009／R016 续修记录](r009-r016-closeout.md)。

目标：以稳定身份和真实来源完成类型化搜索、详情、关联、Home、分页与缓存生命周期，不用 yt-dlp 结果或显示名称冒充官方目录身份。

实施：

1. 用真实响应样本建立 renderer 支持矩阵，逐类补齐歌曲、视频、专辑、艺人、歌单、播客和详情／关联解析；未知形状继续 fail closed，并记录不含凭据的安全诊断。
2. 统一搜索、browse、详情和关联页的 loading、empty、unavailable、stale、retry、cancel 与 continuation 行为；所有 cursor 继续绑定 generation、scope、region 和语言。
3. 完成规范化缓存的 fresh／stale／expired 策略和物理分区；匿名 Home、账号 Web Home、公共目录与本机推荐不得共享授权或真值。
4. 完成榜单地区、语言、发行详情、艺人 discography、播客详情和订阅上传流；每个可播放页面都必须形成正确 collection-context。
5. 在同一 Release 上验证匿名首屏、全局与 shelf continuation、账号 helper 成功／失败／频道不匹配、无网、保存快照、响应形状变化和缓存过期。

完成门槛：

- 六类搜索及其详情、分页、错误和重试有真实网络证据；未知 renderer 不产生伪造内容。
- 地区／语言和榜单来源可解释；账号增强失败明确降级到匿名 baseline，不扩大权限。
- 键盘、VoiceOver、三语言、播放上下文及大结果集滚动通过；性能结论有测量数据。

## 批次 24：R014 播客闭环

目标：在统一 `Track`、`PlaybackService` 和队列体系中提供完整播客节目／单集体验，不创建第二套播放引擎或伪造时间、章节和可用性。

实施：

1. 建立稳定节目与单集身份、节目关注状态、发布时间和可用性模型；普通音乐视频与播客单集继续共享可播放 Track，但媒体类型语义明确。
2. 接入节目详情和完整分页；定义刷新、缓存过期、空态、不可用和账号切换行为。
3. 持久化逐集续播位置、已听／未听状态和完成阈值；恢复、历史和队列仍由现有播放服务统一负责。
4. 增加播客倍速、前后跳转及按发布时间播放未听单集；系统媒体命令、Now Playing 和集合 previous／next 保持一致。
5. 验证重复单集、删除／私密单集、无时长、跨设备输出、冷启动恢复、长节目和分页节目。

完成门槛：

- 关注、分页、续播、已听、倍速、跳转和未听队列均有自动化及真实节目证据。
- 音乐与播客切换不产生双声源、队列错位或历史污染；不可用内容不会进入可播放队列。
- Smart Shuffle 不作为播客父项的替代证据。

## 批次 25：R015 账号内容与互动

目标：把每类账号读取和写入作为独立能力交付，不把本地收藏、导入历史或浏览器页面伪装成远端用户状态。

实施顺序：

1. **R015A 订阅闭环**：为订阅／取消订阅增加精确频道和 subscription resource 预览、逐次确认、服务端复读、响应不确定恢复及真实账号验收。
2. **R015B Shorts**：先确认可用的稳定视频身份、分页来源、播放上下文和不可用状态，再接入统一 Track／队列；没有结构化来源时明确不可用。
3. **R015C 评论**：分别设计读取、发布、回复、编辑和删除；草稿按 OAuth 频道隔离，远端写入带目标预览和确认，失败不产生本地成功幻象。
4. **批准范围保持不变**：稍后观看和远端历史继续打开官方页面；字幕、画质由官方视频播放器实际提供；悬浮视频不称为系统原生 PiP。

完成门槛：

- 每个子能力分别具备 loading、pagination、empty、unavailable、account switch、confirmation、read-back 和 recovery 证据。
- 至少用专用可恢复目标完成订阅／取消订阅真实闭环；评论写入必须另获精确内容和操作授权。
- 未实现或平台不提供的能力明确显示边界，不以本地状态代替远端状态。

## 批次 26：R023 同一 Release 验收

目标：冻结一个候选 Release，在同一构建上完成此前分散或受条件限制的系统验证。

矩阵：

- macOS 14 和其他目标系统；浅色、深色、高对比度、Reduce Motion、Reduce Transparency；英语、简中、繁中。

## 批次 27：OAuth 与正式发布收口

目标：生成不依赖源码目录、可真实登录并可公证分发的正式构建。

实施与门槛：

1. 通过受控构建环境注入 OAuth client 配置，确认产物字段完整；任何 client 配置、token 或浏览器凭据都不得进入 Git、文档、日志和普通缓存。
2. 使用 Developer ID 构建并验证主应用、Web Home helper、entitlements、版本化 IPC、资源包、yt-dlp 和 App Intents 元数据；完成 Apple 公证和 stapling。
3. 在干净用户环境验证首次安装、首次 OAuth、manage scope 升级、退出／重连、授权过期、helper consent、冷启动恢复和卸载后的数据边界。
4. 验证从 `v0.5.0` 的升级和新版本 store 指针，不删除源 store 直到 manifest 完整、冷重启和 legacy-store 缺席验证全部通过。
5. 归档最终测试、实机矩阵、公证和安装证据，再更新发布说明和公开文档。

## 停止条件

- 需要按名称猜测身份、来源不稳定或 renderer 形状未知时停止持久化，只呈现未解析／不可用状态。
- schema 迁移无法证明用户数据逐表守恒时停止激活，不修改源库。
- 真实账号目标、权限或确认不精确时不发送写请求；响应不确定时不重放潜在重复写入。
- 同一 Release 矩阵出现播放可靠性、数据丢失、权限扩大或凭据泄露时，阻止发布并回到所属批次。
